<Update label="October 2026" description="Second try on hosted web paywalls" tags={["Web paywalls", "Dashboard", "iOS SDK"]}>

  **Web paywalls**

  - A hosted web paywall can now show a [second try](/guides/build-app2web-paywall#add-a-second-try) on the checkout page itself, without a reload, when the user taps ✕ or a cancel link, closes the Apple Pay sheet without paying, declines the California consent modal (Paddle), or comes back to the page after leaving it.
  - The web second try is being rolled out and is off until Helium turns it on for your app. [Contact Helium](mailto:founders@tryhelium.com) to turn it on.
  - The second try shows at most once per page load, and never to a user who already has an active subscription. See the [requirements and limits](/guides/build-app2web-paywall#requirements-and-limits).

  **Dashboard**

  - A web paywall can use another web paywall on the same provider as its second try, with a trigger action for each of the moments above.
  - The second try dialog's button is now **Apply**, and a **Pending** badge shows until you **Save and Publish** the paywall.

  **iOS SDK X.Y.Z**

  - Required for the second try on hosted web paywalls. Older app builds show the hosted web paywall without it.
  - Fixed: the events iOS logs to Helium and forwards to your analytics now carry [`isSecondTry`](/guides/helium-events#paywall-and-purchase-events) (`is_second_try` in forwarded events). Earlier versions reported it as `false`.
</Update>
