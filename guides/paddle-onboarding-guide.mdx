Take users from your paywall to web checkout—and back to your app with access unlocked.

## 1. Set up your Paddle account

1. Complete Paddle’s [account setup](https://developer.paddle.com/build/onboarding/set-up-checklist#sign-up), including identity verification, banking, and tax details, to enable live payments.
2. [Create your products and prices](https://developer.paddle.com/build/products/create-products-prices) in Paddle.

## 2. Connect Paddle to Helium

**Create an API key in Paddle** with the following permissions:

| Permission | Purpose |
| :-- | :-- |
| Adjustments  `READ` | View refunds and chargebacks |
| Client-side tokens `WRITE` | Create checkout tokens |
| Customer portal sessions `WRITE` | Create subscription management links |
| Customers `WRITE` | Create customers for end users |
| Discounts `READ` | Read discount info for paywalls |
| Notification settings `WRITE` | Auto-configure webhooks |
| Payment methods `READ` | List saved payment methods |
| Prices `WRITE` | Create and sync prices |
| Products `WRITE` | Create and sync products |
| Subscriptions `WRITE` | Manage subscription lifecycle |
| Transactions `WRITE` | Create transactions for purchases |

**Add the API key to Helium.** In the Helium dashboard, go to _Settings → Integrations → Paddle_ and paste your key.

**Configure the webhook.** Helium will show you a webhook URL — create a matching webhook in Paddle, then copy the webhook's signing secret back into Helium. This powers revenue reporting and entitlement updates.

## 3. Set up the payment link

1. Go to [Paddle website approval](https://vendors.paddle.com/request-domain-approval) and add a new domain.
2. Go to [Paddle Checkout Settings](https://vendors.paddle.com/checkout-settings) and find the **Default payment link** section. Paste in the same domain you just added for **Paddle website approval**.
3. On the same page, enable **Apple Pay** under **Payment Methods**.

## 4. Sync your Paddle products

In the Helium dashboard, click **Sync Products**. Your Paddle products and prices will appear alongside your iOS products and can be added to paywalls.

<Accordion title="Optional: add free trials">
**Each trial price needs a linked non-trial price.**

1. Create a trial price and a matching non-trial price in Paddle, then sync them to Helium.
2. Link the trial and non-trial prices in Helium so the paywall can offer the appropriate purchase option.
3. Use a **separate non-trial price for every trial offer** you launch—even if the amount is the same. This lets you identify which offer a non-trial purchase came from.

Helium limits trials to one per customer, including after cancellation. Trials require a payment method up front.
</Accordion>

## 5. Build your paywalls

Your in-app paywall opens a linked web paywall when the user purchases a Paddle product. The user completes payment in the browser, then returns to your app.

1. Add Paddle products to your in-app paywall. Include iOS products for the in-app purchase option.
2. Create and link a hosted web paywall for browser checkout on `clickthrough.to`.
3. Publish both paywalls. Target the **in-app paywall** to eligible users; the hosted paywall cannot be added directly to workflows or experiments.

See [Build an App2Web paywall](/guides/build-app2web-paywall) for the walkthrough.

<Accordion title="Supported platforms and languages">
  App2Web is iOS-only and limited to US storefronts. Hosted paywalls currently support one language. On Android, the React Native and Flutter web-checkout APIs are safe no-ops; keep your regular IAP flow.
</Accordion>

## 6. Add web checkout to your app

Choose your SDK, then enable checkout, identify your user, handle the return link, and add subscription management.

<Tabs>
  <Tab title="iOS (native, Helium 4.6.0+)">
    **Enable checkout before initializing Helium:**

    ```swift
    Helium.config.enableExternalWebCheckout(
      redirectURL: "yourapp://openapp",
      paymentProcessors: .paddle
    )
    ```

    Use your registered deep link as `redirectURL`. Checkout returns here after success, cancellation, or failure.

    <Accordion title="Using an older SDK?">
      On older SDK versions that don't have `redirectURL`, use the equivalent two-URL form with the same URL for both: `enableExternalWebCheckout(successURL:cancelURL:paymentProcessors:)`. That form still works, but is deprecated.
    </Accordion>

    **Set your user ID on Helium** before showing a paywall.

    <Accordion title="Purchases before sign-in">
      If you must set the user ID after showing a paywall, set `allowWebCheckoutWithoutUserId` to `true`.
    </Accordion>

    **Handle the return link.** Forward incoming links to `Helium.shared.handleURL(url)` from your `onOpenURL` / `application(_:open:)` handler.

    **Add a "Manage Subscription" button** so users can cancel or update payment methods via Paddle's customer portal:

    ```swift
    if await Helium.entitlements.hasActivePaddleEntitlement() {
        // show the manage subscription button
    }
    
    // when the button is tapped:
    do {
        let url = try await Helium.shared.createPaddlePortalSession()
        UIApplication.shared.open(url)
    } catch {
        print("Failed to open customer portal: \\(error)")
    }
    ```

    The portal opens `paddle.net`; users sign in with their purchase email.

    <Accordion title="Optional: pre-authenticated portal links">
    If you'd rather skip the paddle.net email verification step and drop users straight into the customer portal, generate the link from your backend instead. Look up the user's Paddle customer ID with Helium:

    ```swift
    let paddleCustomerId = await Helium.shared.getPaddleCustomerId()
    ```

    Send that ID to your server and follow [Paddle's guide for generating pre-authenticated customer portal links](https://developer.paddle.com/build/customers/integrate-customer-portal/).
    </Accordion>
  </Tab>
  <Tab title="React Native / Expo">
    Available in `expo-helium` 3.4.13\+ and `@tryheliumai/paywall-sdk-react-native` 3.1.2\+.

    **Enable checkout before initializing Helium:**

    ```tsx
    enableExternalWebCheckout({
      redirectURL: "yourapp://openapp",
      paymentProcessors: ["paddle"],
    });
    ```

    Use your registered deep link as `redirectURL`. Checkout returns here after success, cancellation, or failure.

    <Accordion title="Using an older SDK?">
      On older SDK versions that don't have `redirectURL`, pass the equivalent `successURL` and `cancelURL` parameters with the same URL for both. That form still works, but is deprecated.
    </Accordion>

    **Set your user ID on Helium** before showing a paywall.

    <Accordion title="Purchases before sign-in">
      If you must set the user ID after showing a paywall, call `setAllowWebCheckoutWithoutUserId(true)`.
    </Accordion>

    **Handle the return link.** Forward incoming links to `heliumHandleURL(url)` from your deep link handling:

    ```tsx
    useEffect(() => {
      const sub = Linking.addEventListener('url', (event) => heliumHandleURL(event.url));
      void Linking.getInitialURL().then(heliumHandleURL);
      return () => sub.remove();
    }, []);
    ```

    <Note>
      With **Expo Router**, you may need to [override the default behavior](https://docs.expo.dev/router/advanced/native-intent/#sending-navigation-events-to-third-party-services).
    </Note>

    **Add a "Manage Subscription" button** so users can cancel or update payment methods via Paddle's customer portal:

    ```tsx
    if (await hasActivePaddleEntitlement()) {
        // show the manage subscription button
    }
    
    // when the button is tapped:
    const url = await createPaddlePortalSession();
    if (url) {
      await Linking.openURL(url);
    }
    ```

    The portal opens `paddle.net`; users sign in with their purchase email.

    <Accordion title="Optional: pre-authenticated portal links">
    If you'd rather skip the paddle.net email verification step and drop users straight into the customer portal, generate the link from your backend instead. Look up the user's Paddle customer ID with Helium:

    ```tsx
    const paddleCustomerId = await getPaddleCustomerId();
    ```

    Send that ID to your server and follow [Paddle's guide for generating pre-authenticated customer portal links](https://developer.paddle.com/build/customers/integrate-customer-portal/).
    </Accordion>
  </Tab>
  <Tab title="Flutter (Helium 3.3.8+)">
    **Enable checkout before initializing Helium:**

    ```dart
    await HeliumFlutter().enableExternalWebCheckout(
      redirectURL: "yourapp://openapp",
      paymentProcessors: {HeliumWebCheckoutProcessor.paddle},
    );
    ```

    Use your registered deep link as `redirectURL`. Checkout returns here after success, cancellation, or failure.

    <Accordion title="Using an older SDK?">
      On older SDK versions that don't have `redirectURL`, pass the equivalent `successURL` and `cancelURL` parameters with the same URL for both. That form still works, but is deprecated.
    </Accordion>

    <Accordion title="Register a Flutter deep link">
    For a custom scheme, add a `CFBundleURLTypes` entry to `ios/Runner/Info.plist`:

    ```xml
    <key>CFBundleURLTypes</key>
    <array>
      <dict>
        <key>CFBundleURLName</key>
        <string>com.yourcompany.yourapp</string>
        <key>CFBundleURLSchemes</key>
        <array>
          <string>yourapp</string>
        </array>
      </dict>
    </array>
    ```

    To use a universal link (`https://...`) instead, set up [associated domains](https://docs.flutter.dev/ui/navigation/deep-linking) and use that URL as the `redirectURL`.
    </Accordion>

    **Set your user ID on Helium** before showing a paywall.

    <Accordion title="Purchases before sign-in">
      If you must set the user ID after showing a paywall, call `setAllowWebCheckoutWithoutUserId(true)`.
    </Accordion>

    **Handle the return link.** Forward incoming links to `handleURL(url)`; Helium ignores unrelated URLs. If you don’t already handle deep links, add [app_links](https://pub.dev/packages/app_links) with `flutter pub add app_links`:

    ```dart
    import 'package:app_links/app_links.dart';

    _linkSubscription = AppLinks().uriLinkStream.listen((uri) {
      HeliumFlutter().handleURL(uri.toString());
    });
    ```

    <Note>
      `uriLinkStream` also emits the link that launched the app, so cold starts are covered — there is no separate initial-link step. If you use `app_links`, set `FlutterDeepLinkingEnabled` to `false` in `Info.plist` so Flutter's built-in deep-link handling doesn't consume the link first.
    </Note>

    **Add a "Manage Subscription" button** so users can cancel or update payment methods via Paddle's customer portal. `launchUrl` comes from the [url_launcher](https://pub.dev/packages/url_launcher) package:

    ```dart
    final hasPaddle = await HeliumFlutter().hasActivePaddleEntitlement();
    if (hasPaddle) {
        // show the manage subscription button
    }

    // when the button is tapped:
    final urlString = await HeliumFlutter().createPaddlePortalSession();
    if (urlString != null) {
      await launchUrl(Uri.parse(urlString));
    }
    ```

    The portal opens `paddle.net`; users sign in with their purchase email.

    <Accordion title="Optional: pre-authenticated portal links">
    If you'd rather skip the paddle.net email verification step and drop users straight into the customer portal, generate the link from your backend instead. Look up the user's Paddle customer ID with Helium's `getPaddleCustomerId()`, send it to your server, and follow [Paddle's guide for generating pre-authenticated customer portal links](https://developer.paddle.com/build/customers/integrate-customer-portal/).
    </Accordion>
  </Tab>
</Tabs>

## 7. Configure your entitlements

**Use Helium—the simplest way to unlock access after a web purchase.** Check the user’s Paddle entitlement in one line:

<Tabs>
  <Tab title="iOS">
    ```swift
    let hasWebAccess = await Helium.entitlements.hasActivePaddleEntitlement()
    ```
  </Tab>
  <Tab title="React Native / Expo">
    ```tsx
    const hasWebAccess = await hasActivePaddleEntitlement();
    ```
  </Tab>
  <Tab title="Flutter">
    ```dart
    final hasWebAccess = await HeliumFlutter().hasActivePaddleEntitlement();
    ```
  </Tab>
</Tabs>

Use this result alongside your existing in-app purchase checks to unlock paid features. Helium updates the entitlement after purchase and tracks subsequent subscription changes through the webhook you connected in step 2.

For details on identity and entitlement updates, see [Paddle App2Web entitlements](/guides/paddle-entitlements).

Already have an entitlement system? You can connect it instead:

<AccordionGroup>

<Accordion title="Use RevenueCat for entitlements">
Connect Paddle purchases to your existing RevenueCat entitlements:

1. Create a Paddle web configuration in the [RevenueCat dashboard](https://app.revenuecat.com).
   1. Select your project \> **Web** \> Add web provider \> Paddle
   2. Create a new [Paddle API Key](https://vendors.paddle.com/authentication-v2) for RevenueCat. **See permissions below**
   3. Paste in the new Paddle API key
   4. Purchase tracking should be **Automatic**
   5. Under **App user ID matching** select **Use a custom field** with `rc_user_id` as the field key
2. Go to **Product catalog** \> **Products** and Import your Paddle products into RevenueCat.
3. Attach those products to desired entitlement(s).

<Accordion title="Permissions for Paddle API Key that RevenueCat needs">
  - Addresses  `READ`
  - Adjustments - `READ`
  - Businesses - `READ`
  - Client-side tokens - `WRITE`
  - Customer portal sessions - `WRITE`
  - Customers - `READ`
  - Discounts - `READ`
  - Notification settings - `WRITE`
  - Notifications - `READ`
  - Payment methods - `READ`
  - Prices - `READ`
  - Products - `READ`
  - Subscriptions - `READ`
  - Transactions - `WRITE`
</Accordion>

RevenueCat can take a few seconds to reflect a purchase. Check Helium entitlements as well to unlock access immediately while RevenueCat syncs.

<Accordion title="Troubleshooting RevenueCat Entitlements for Paddle Purchases">
  - Make sure you have done the above steps and include all of your Paddle products in your RevenueCat entitlements.
  - Find your Paddle -\> RevenueCat webhook at [https://vendors.paddle.com/notifications-v2](https://vendors.paddle.com/notifications-v2) and click on it to see that notifications are being sent successfully. If you see errors, you may need to adjust the permissions on the Paddle API Key you provided to RevenueCat.
  - If you still have issues, delete the existing Paddle web provider in RevenueCat, revoke the Paddle API Key you created for RevenueCat (leave the Helium one), and run through the above steps again.
</Accordion>

## 8. Test everything

Create a test audience with **Paddle eligible users** and the **`sandbox` or `debug` app environment**. Target your in-app App2Web paywall to it.

You can also test via **[Helium’s triple-tap flow](/guides/paywall-previews#preview-paywalls-from-your-app)**: open a Helium paywall in your test build, triple-tap it, and select your App2Web paywall. [App2Web previews](/guides/app2web-previews) support simulated checkout to check the flow without a charge; simulated purchases do not grant entitlements. Real checkout charges the payment method and lets you verify access.

- **Purchase:** open a real trigger → browser checkout → purchase → return to the app. Confirm access unlocks in your chosen entitlement system and `hasActivePaddleEntitlement()` returns `true`.
- **Dismiss or cancel checkout:** return to the expected screen without granting access or showing success.
- **Manage subscription:** open the customer portal, cancel, and confirm access lasts until period end.
- **Webhooks:** confirm Paddle delivers to Helium with 2xx responses.

<Accordion title="If you use RevenueCat or allow purchases before sign-in">
  - Confirm RevenueCat updates within a few seconds of purchase, if connected.
  - If users can buy before you set a durable user ID, purchase first, then set the ID and confirm the entitlement attaches correctly.
</Accordion>

<Accordion title="App2Web paywall not appearing?">
  The device locale country, App Store storefront, and IP location must all be US. From the US, disable VPNs. From outside the US, use a US device region, a US sandbox Apple storefront, and a US VPN.
</Accordion>

### Before you go live

Finish the [App2Web go-live checklist](/guides/app2web-go-live-checklist), then start with a small eligible audience. Test through a real trigger before launch—previews bypass targeting, paywall traits, and post-purchase handlers.

See the [App2Web FAQ](/guides/app2web-faq) for attribution, checkout behavior, and experiment results.
