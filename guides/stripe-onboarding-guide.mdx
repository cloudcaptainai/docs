Connect Stripe, build your checkout, and add the SDK calls below.

**Before you start:** have the Helium SDK integrated, admin access to Helium, and a registered deep link or universal link to return users to your app.

## 1. Connect Stripe to Helium

Go to the Helium [Integrations](https://app.tryhelium.com/integrations/products) page, click the Stripe tab, and **Connect Stripe**.

Create a new account or connect an existing Stripe account.

Sync your products and ensure the APPLE PAY DOMAIN status is Verified.

<Info>
  Helium does not yet support Stripe sandbox.
</Info>

## 2. Adjust Stripe Products

Assign Stripe products to appropriate buckets. Add free/paid trials as needed.

## 3. Build your paywalls

1. Add Stripe products to your in-app paywall. Include iOS products for the in-app purchase option.
2. Create and link a hosted web paywall for browser checkout on `clickthrough.to`.
3. Publish both paywalls. Target the **in-app paywall** to eligible users; the hosted paywall cannot be added directly to workflows or experiments.

See [Build an App2Web paywall](/guides/build-app2web-paywall) for the walkthrough. Hosted paywalls currently support one language.

## 4. Add web checkout to your app

<Tabs>
  <Tab title="iOS (native, Helium 4.6.0+)">
    **Enable external web checkout before initializing Helium:**

    ```swift
    Helium.config.enableExternalWebCheckout(
      redirectURL: "yourapp://openapp",
      paymentProcessors: .stripe
    )
    ```

    Use your registered deep link as `redirectURL`. Checkout returns here after success, cancellation, or failure.

    <Accordion title="Using an older SDK?">
      On older SDK versions that don't have `redirectURL`, use the equivalent two-URL form with the same URL for both: `enableExternalWebCheckout(successURL:cancelURL:paymentProcessors:)`. That form still works, but is deprecated.
    </Accordion>

    **Set your user ID on Helium** before showing a paywall.

    <Accordion title="Purchases before sign-in">
      If you must set the user ID after showing a paywall, set `allowWebCheckoutWithoutUserId` to `true`.
    </Accordion>

    **Handle the checkout return.** Whether checkout succeeds, is canceled, or fails, the user is deep-linked back to your app via the redirect URL. For a smoother handoff, call `Helium.shared.handleURL(url)` from your `onOpenURL` / `application(_:open:)` handler.

    **Add a "Manage Subscription" button** so users can cancel or update payment methods via Stripe's customer portal:

    ```swift
    if await Helium.entitlements.hasActiveStripeEntitlement() {
        // show the manage subscription button
    }
    
    // when the button is tapped:
    do {
        let url = try await Helium.shared.createStripePortalSession()
        UIApplication.shared.open(url)
    } catch {
        print("Failed to open customer portal: \\(error)")
    }
    ```
  </Tab>
  <Tab title="Expo (Helium 3.4.13+)">
    **Enable external web checkout before initializing Helium:**

    ```tsx
    enableExternalWebCheckout({
      redirectURL: "yourapp://openapp",
      paymentProcessors: ["stripe"],
    });
    ```

    Use your registered deep link as `redirectURL`. Checkout returns here after success, cancellation, or failure.

    <Accordion title="Using an older SDK?">
      On older SDK versions that don't have `redirectURL`, pass the equivalent `successURL` and `cancelURL` parameters with the same URL for both. That form still works, but is deprecated.
    </Accordion>

    **Set your user ID on Helium** before showing a paywall.

    <Accordion title="Purchases before sign-in">
      If you must set the user ID after showing a paywall, call `setAllowWebCheckoutWithoutUserId(true)`.
    </Accordion>

    **Handle the checkout return.** Whether checkout succeeds, is canceled, or fails, the user is deep-linked back to your app via the redirect URL. For a smoother handoff, call `heliumHandleURL(url)` from your deep link handling:

    ```tsx
    useEffect(() => {
      const sub = Linking.addEventListener('url', (event) => heliumHandleURL(event.url));
      void Linking.getInitialURL().then(heliumHandleURL);
      return () => sub.remove();
    }, []);
    ```

    <Note>
      You do not need to do anything with the links other than forward them to `heliumHandleURL` like shown above. If you are using **Expo Router** you may need to [override the default behavior](https://docs.expo.dev/router/advanced/native-intent/#sending-navigation-events-to-third-party-services).
    </Note>

    **Add a "Manage Subscription" button** so users can cancel or update payment methods via Stripe's customer portal:

    ```tsx
    if (await hasActiveStripeEntitlement()) {
        // show the manage subscription button
    }
    
    // when the button is tapped:
    const url = await createStripePortalSession();
    if (url) {
      await Linking.openURL(url);
    }
    ```
  </Tab>
  <Tab title="Flutter (Helium 3.3.8+)">
    **Enable external web checkout before initializing Helium:**

    ```dart
    await HeliumFlutter().enableExternalWebCheckout(
      redirectURL: "yourapp://openapp",
      paymentProcessors: {HeliumWebCheckoutProcessor.stripe},
    );
    ```

    Use your registered deep link as `redirectURL`. Checkout returns here after success, cancellation, or failure.

    <Accordion title="Using an older SDK?">
      On older SDK versions that don't have `redirectURL`, pass the equivalent `successURL` and `cancelURL` parameters with the same URL for both. That form still works, but is deprecated.
    </Accordion>

    **Set your user ID on Helium** before showing a paywall.

    <Accordion title="Purchases before sign-in">
      If you must set the user ID after showing a paywall, call `setAllowWebCheckoutWithoutUserId(true)`.
    </Accordion>

    **Handle the checkout return.** Whether checkout succeeds, is canceled, or fails, the user is deep-linked back to your app via the redirect URL. For a smoother handoff, call `handleURL(url)` from your deep link handling:

    ```dart
    _linkSubscription = AppLinks().uriLinkStream.listen((uri) {
      HeliumFlutter().handleURL(uri.toString());
    });
    ```

    **Add a "Manage Subscription" button** so users can cancel or update payment methods via Stripe's customer portal:

    ```dart
    final hasStripe = await HeliumFlutter().hasActiveStripeEntitlement();
    if (hasStripe) {
        // show the manage subscription button
    }
    
    // when the button is tapped — returnUrl is where Stripe sends the user
    // back after they're done managing their subscription:
    final urlString = await HeliumFlutter().createStripePortalSession(
      returnUrl: "yourapp://openapp",
    );
    if (urlString != null) {
      await launchUrl(Uri.parse(urlString));
    }
    ```
  </Tab>
</Tabs>

The customer portal requires email sign-in.

<Accordion title="Optional: pre-authenticated portal links">
  To skip email sign-in, create a [pre-authenticated link](https://docs.stripe.com/customer-management/integrate-customer-portal) from your backend.
</Accordion>

## Testing

Create a test audience with **Stripe eligible users** and the **`sandbox` or `debug` app environment**. Target your in-app App2Web paywall to it.

**Stripe sandbox is not supported:** an app's `sandbox` or `debug` environment does not make the payment a test transaction.

- **Purchase:** open a real trigger → browser checkout → purchase → return to the app with an active entitlement. Confirm `hasActiveStripeEntitlement()` returns `true`.
- **Dismiss or cancel checkout:** return to the expected screen without granting access or showing success.
- **Manage subscription:** open the customer portal, cancel, and confirm access lasts until period end.

<Accordion title="If you use RevenueCat or allow purchases before sign-in">
  - Confirm RevenueCat updates within a few seconds of purchase, if connected.
  - If users can buy before you set a durable user ID, purchase first, then set the ID and confirm the entitlement attaches correctly.
</Accordion>
